# 06. Reproduction guide: environment, data, training and evaluation

## 0. Two meanings of "reproduce"

1. **Numerical reproduction (deterministic)**: use the bundled `best.pt`
   checkpoints + `annotations/` + Common Evaluator to recompute the test metrics
   on any CUDA machine. A/B seed0 have been verified to match the paper
   (see `docs/05_weight_inventory.md`).
2. **Training reproduction (statistical)**: start from `yolo11n.pt`, train
   three seeds under the paper hyperparameters. GPU/CUDA/cuDNN/PyTorch
   non-determinism means bit-identical weights are not guaranteed, but the
   split, seeds, hyperparameters and evaluator are fixed, so mean/SD should be at
   the same level.

## 2. Data preparation

### 2.1 Dataset A

Get the RGB subset from the Mendeley Data record of Zhang et al.
(doi:10.17632/6svnttj9g4.2, v2; v1: doi:10.17632/6svnttj9g4.1; paper:
arXiv:2510.16800) and reconstruct the fixed split with
`data/dataset_a/split_manifest.csv`:

```text
<Dataset A root>/
|-- images/train/   # 590 originals + 1,770 augmented = 2,360
|-- images/val/     # 126 originals
|-- images/test/    # 126 originals
|-- labels/train/   # 2,360 .txt
|-- labels/val/
|-- labels/test/
`-- lychee_groupaware_clean_aug_v2.yaml
```

The YAML can be the original one, or generated by `run_reproduction.py` from
`--dataset-root`. `images/train` must contain the **2,360 augmented images**;
using only the 590 originals gives a different training distribution. The
per-image augmentation parameters are in `data/dataset_a/augmentation_log.csv`;
the rules are in `augmentation_scheme.txt`.

### 2.2 Dataset B

Get `lichi-maturity` from Mendeley Data V1 and reconstruct with
`data/dataset_b/split_manifest.csv`:

```text
<Dataset B root>/
|-- train/images/   # 1,071 originals + 3,213 augmented = 4,284
|-- train/labels/
|-- val/images/     # 212 originals (byte-identical)
|-- val/labels/
|-- test/images/    # 212 originals (byte-identical)
|-- test/labels/
`-- lichi_maturity_groupaware_clean_v4_aug.yaml
```

Augmentation parameters are in `data/dataset_b/augmentation_summary.json` and
`augmentation_log.csv`.

## 3. Train + validate + Common Evaluator

### 3.1 One-command entry

```bash
# Dataset A: both models x 3 seeds
python train/run_reproduction.py \
  --dataset a \
  --dataset-root /path/to/lychee_groupaware_clean_aug_v2 \
  --seeds 0 1 2

# Dataset B
python train/run_reproduction.py \
  --dataset b \
  --dataset-root /path/to/lichi_701515_groupaware_clean_v4_aug \
  --seeds 0 1 2
```

Print commands only:

```bash
python train/run_reproduction.py --dataset a --dataset-root ... --plan-only
```

Evaluate existing checkpoints only:

```bash
python train/run_reproduction.py --dataset a --dataset-root ... --skip-train
```

Run one model/seed:

```bash
python train/run_reproduction.py --dataset a --dataset-root ... \
  --models FSDH-YOLO --seeds 0
```

### 3.2 Actual commands

For each model x seed:

```text
# Train
python train/origin_train.py \
  --model <yolo11n.pt or configs/yolo11n_FSDConv-SHAB.yaml> \
  --data <runtime yaml> \
  --project runs/<a|b>/train \
  --name <run_name> \
  --epochs 300 --batch 12 --imgsz 640 \
  --workers 6 --val-workers 2 --patience 100 \
  --seed <0|1|2> --fraction 1.0 --iou-type ciou
  [FSDH adds: --weights weights/pretrained/yolo11n.pt --weights-map none]

# Independent test (native Ultralytics)
python train/val.py \
  --model runs/<a|b>/train/<run_name>/weights/best.pt \
  --data <runtime yaml> \
  --project runs/<a|b>/test \
  --name <run_name>_test \
  --batch 16 --imgsz 640

# Common Evaluator
python eval/eval_ultralytics_common_evaluator.py \
  --model runs/<a|b>/train/<run_name>/weights/best.pt \
  --model-name <YOLO11n|FSDH-YOLO|FSDH-YOLO-n> \
  --seed <0|1|2> \
  --images <test images> \
  --annotations annotations/dataset_<a|b>_test_instances.json \
  --out runs/<a|b>/common_eval/<model>/seed<N>__test_metrics_common.json \
  --predictions-out runs/<a|b>/common_eval/<model>/seed<N>__test_predictions_coco.json \
  --imgsz 640 --device 0 --conf 0.001 --iou 0.7 --max-det 300 \
  --bins 15 --area-scale <A=4|B=1>
```

### 3.3 Training hyperparameters (paper Table 2)

| Parameter | Value |
|---|---|
| Input | 640x640 |
| batch | 12 |
| workers / val workers | 6 / 2 |
| optimizer | SGD |
| momentum | 0.937 |
| epochs | 300 |
| lr0 / lrf | 0.01 / 0.01 |
| warm-up | 3 (Ultralytics default) |
| weight decay | 0.0005 |
| patience | 100 |
| seeds | 0/1/2 |
| AMP | on |
| deterministic | on |
| close_mosaic | 0 |
| pretrained | `yolo11n.pt`; FSDH new modules initialized from seed |

> `origin_train.py` currently hard-codes training `device="0"`. If you only have
> CPU or a different GPU index, edit that line. Evaluation `--device` is separate.

### 3.4 Early stopping and actual epochs

The paper says 300 epochs, but patience=100 triggers early stopping. Actual best
epochs in the original runs:

| Dataset | Model | seed0 | seed1 | seed2 |
|---|---|---:|---:|---:|
| A | FSDH-YOLO | 63 | 74 | 52 |
| A | YOLO11n | 41 | 130 | 44 |
| B | FSDH-YOLO-n | 82 | 81 | 77 |
| B | YOLO11n | 59 | 74 | 52 |

This is consistent with "300 epochs + patience 100"; the paper reports the
early-stopped best.pt.

## 5. Latency (optional)

`train/run_reproduction.py --latency` builds a manifest and calls:

```bash
PYTHONPATH=src python eval/benchmark_uniform_latency.py \
  --manifest <run_dir>/latency_manifest.csv \
  --image <test image> \
  --out <run_dir> \
  --imgsz 640 --warmup 100 --iterations 500
```

Manifest format:

```csv
section,model,seed,weights,imgsz
dataset_a,FSDH-YOLO,0,weights/dataset_a/FSDH-YOLO_n_seed0_best.pt,640
```

Protocol: CUDA FP32, batch=1, 640x640; warm-up 100, timing 500; CUDA sync before
and after each measured forward; timing includes forward + decode + class-aware
NMS (conf 0.25, IoU 0.70, max_det 300); excludes image loading/preprocessing.
Outputs `uniform_latency_results.csv` / JSON.

> Paper FPS is the mean+/-SD of three independently timed seed checkpoints, not
> the SD of 500 repeated forward passes of one model.

## 7. Common pitfalls

1. **Never re-randomize the split**: use `group_id` from
   `split_manifest.csv`; near-duplicate frames across splits inflate metrics.
2. **Dataset A train must include augmentation**: 2,360 images, not 590.
3. **Dataset B `young=3`**: do not use class ID as maturity order.
4. **A/B area scales differ**: A `--area-scale 4`, B `--area-scale 1`.
5. **Evaluation conf vs timing conf**: evaluation 0.001; timing NMS 0.25;
   Android app 0.25 / IoU 0.45.
6. **Native val vs Common Evaluator**: paper tables use the latter; native val
   only selects best.pt.
7. **Params use fused values**: 2.997 M, not 3.020 M.
8. **`--weights-map`**: paper runs use `none` (native name/shape transfer);
   `fsdh_yolo11n` is a semantic-layer mapping option for specific controls.
9. **Training device is hard-coded to "0"** in `origin_train.py`; edit for
   multi-GPU/CPU.
10. **Dataset A annotation lacked `info.split`**: use the corrected copy.
11. **Do not mix A/B checkpoints**: 3-class vs 4-class heads.
12. **Early stopping**: actual epochs are not 300; use `best.pt` and the best
    epoch in `results.csv`.
